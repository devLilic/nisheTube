# QA-04 — YouTube researcher end-to-end acceptance

## Goal and boundaries

Protect the complete redesigned researcher workflow from locale selection through evidence-backed decision and organization. Add regression coverage only; do not expand feature scope.

## Acceptance

- The acceptance path covers Romanian default, responsive navigation, Research creation, results, Explore, format comparison, competitor analysis, section-scoped Comments/Thumbnail work, Small Creator Fit, idea generation, and project save.
- Cross-user records and actions remain inaccessible; provider work and quota occur only at explicit documented steps.
- Opportunity, confidence, profitability fit, user-entered commercial scenarios, evidence, and generated ideas remain semantically distinct.
- Partial, unavailable, legacy, failed, retry, reduced-motion, and opaque glass fallback states are included.
- Focused cross-stack tests and final designer review pass without running aggregate suites.

## Applicable decisions

- D-005–D-054.

## Initial inspection targets

- Focused feature/unit/frontend suites for every Phase 23–27 vertical slice and the documented researcher path.

## Relevant contracts and UI

- Existing domain, provider, authorization, immutable snapshot, localization, async, and design contracts are acceptance subjects, not bypassed fixtures.

## Focused verification

- Exact test files covering the end-to-end path, authorization, quota, immutability, localization, async continuity, accessibility, and responsive presentation.
