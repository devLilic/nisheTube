# L10N-01 — Romanian and English localization foundation

## Goal and boundaries

Introduce a persistent UI locale independent from YouTube research market/language. Implement infrastructure, preference ownership, fallback, and selectors; full copy migration belongs to L10N-02.

## Acceptance

- `ui_locale` supports `ro` and `en`; Romanian is the default for guests, existing users, and new users, with English fallback.
- Resolution order is authenticated preference, guest session, Romanian default, English key fallback.
- Public/auth and Settings selectors persist safely; registration adopts the guest locale.
- Shared Inertia props and typed frontend catalogs expose locale without changing market, relevance language, provider calls, or evidence.
- Laravel validation/flash copy, HTML `lang`, and locale-aware numbers/dates have explicit fallback and owner-isolation tests.

## Applicable decisions

- D-005–D-008, D-049, D-052, D-054.

## Initial inspection targets

- User/preference schema and validation, Inertia middleware, app bootstrap, locale config, Settings preferences, auth/landing layouts, formatters.

## Relevant contracts and UI

- `UiLocale = 'ro' | 'en'`.
- Shared props: `locale`, `fallbackLocale`, `supportedLocales`.
- Source YouTube titles, descriptions, comments, and frozen research fields are never translated.

## Focused verification

- Exact feature tests for guest/user resolution, persistence, authorization, registration, and fallback.
- Exact frontend catalog/type/selector tests plus scoped lint/format/type checks.
