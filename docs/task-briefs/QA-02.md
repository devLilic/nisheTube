# QA-02 — Decision-workflow acceptance and regression suite

## Goal and boundaries

Add focused acceptance and regression coverage for the established decision workflow: Discover, select, validate, compare, decide, and monitor. Cover only existing product behavior and fixed requirements; do not introduce provider collection, mutate immutable evidence, redesign interfaces, or expand the workflow.

## Acceptance

- Focused calculation and feature coverage protects owner scope, immutable snapshots, explicit evidence provenance, and accurate opportunity/profitability distinctions.
- Discovery and validation coverage prevents weak candidates from overclaiming, verifies selection limits and foreign-target rejection, and keeps quota language and configuration accurate.
- Frontend and cross-stack cases verify the complete decision hierarchy, keyboard-accessible desktop interactions, explicit partial/unavailable outcomes, and production navigation.
- The workflow from Discover through monitoring takes no more than five meaningful decision steps in the documented acceptance path.
- Focused verification and documentation record all covered outcomes and remaining manual checks.

## Applicable decisions

- D-005–D-008: User-owned reads, writes, and navigation state remain private and authorized.
- D-009–D-013: Provider boundaries, quota accounting, retry behavior, and secret safety remain intact.
- D-014–D-018: Completed research runs and metric snapshots remain immutable and reproducible.
- D-038: Desktop keyboard access, focus behavior, and exact visible values remain required.
- D-041–D-042: Mixed, partial, unavailable, estimated, and calculated outcomes remain explicit.

## Initial inspection targets

- Focused feature and unit tests covering Discovery, Research, Analyzer comparison, Topic Workspaces, Watchlist, and bulk actions.
- Existing frontend interface and accessibility tests for the decision workflow surfaces.
- The documented decision-workflow acceptance path and current app navigation.

## Relevant contracts and UI

- Existing domain actions, Form Requests, policies, immutable model constraints, and provider contracts are the behavior under test; tests must not bypass them.
- Assertions must use owner-scoped routes and records and must not introduce fixture secrets or provider calls.
- Interface assertions must retain exact values, accessible keyboard/focus paths, explicit state labels, and stored-evidence terminology.
- Test additions must be bounded to the active workflow and must not trigger aggregate verification suites.

## Focused verification

- Exact unit/feature tests for the acceptance path and authorization, calculation, quota-language, immutability, partial-state, and selection behavior they cover.
- Exact frontend tests for decision hierarchy, navigation, keyboard access, text alternatives, and explicit outcome states.
- Formatter, lint, type, Pint, and PHPStan checks only for files changed by QA-02.
